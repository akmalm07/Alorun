# Feature implementation tracker

Last source review: **2026-11-17**, based on merged `main` commit `d198e3c`.

This file records what exists; [SPEC.md](SPEC.md) defines intended product behavior. **Check this tracker and inspect the linked code before building anything.** Extend existing implementations instead of creating parallel replacements. Files or dependencies alone are not proof of a complete feature.

## Status meanings

- **Implemented**: a working code path exists. This does not imply production deployment, real-provider verification, or native-device acceptance.
- **Partial**: some behavior exists; the gap column identifies what remains.
- **Schema only**: tables/configuration exist, but the application feature is not implemented.
- **Planned**: specification/design only; no working application path found in the reviewed source.
- Deployment is **unverified** unless a dated deployment record provides evidence. Never infer live status from a Dockerfile, Terraform, cron SQL, or a successful bundle.

## Required agent workflow and upkeep

1. Before planning, search this file for the feature and synonyms; inspect its linked source, endpoints, schemas, migrations, tests and ADRs. Record the relevant IDs and **existing behavior → requested gap** in the task log.
2. An implemented feature with missing credentials, unverified deployment, a defect or a small missing subfeature is an integration/verification/fix task—not permission to rebuild it. Check both chat implementations before touching chat, encryption, voice or branching.
3. If no row matches, search the repository before declaring the feature absent. Add a row with evidence. When tracker and code disagree, inspect the code, correct the tracker and explain the discrepancy; do not blindly trust either stale prose or a table name.
4. Update affected rows in the same change as implementation, removal, verification or deployment. Keep stable IDs; split partial work into existing and missing portions. Include source/test links, actual checks/date/revision, unresolved gaps and deployment evidence. Never promote schema-only or configured-only work to implemented/live.
5. Keep this tracker about current state, SPEC about requirements, ADRs about decisions, and task reports about historical execution. A feature is not production-ready merely because its code is implemented here.
