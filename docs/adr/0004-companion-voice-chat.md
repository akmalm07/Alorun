# 0004: Companion chat and voice session transcripts

The user requested conversational problem solving, voice-to-text input, and voice chat transcribed into the conversation when it ends. Reuse OpenAI transcription and Responses behind the existing provider interface. Use Expo Speech and the device's installed voice for spoken replies. This is explicit record/send, turn-based voice chat; continuous real-time audio is not implied.

Companion replies are grounded in bounded owned goals/tasks plus bounded client conversation. Client history is untrusted conversational context, never evidence of task completion. Model output is reply text plus an optional owned goal ID for a proposal affordance. It has no executable tools. Existing deterministic plan approval writes tasks/calendar; the execution-layer design documents future tool permissions and outcome checking without claiming those future tools are built.

Dictation produces an editable draft and never auto-sends it. Voice session turns stay temporary in client memory until End voice chat merges them into the text conversation. Save-chat-history consent is separate from graph memory and defaults off. When enabled, completed messages are written into the existing chat_threads/chat_messages tables using authenticated ownership and AES-256-GCM application encryption with per-message associated data (owner/thread/message IDs). A server-only 32-byte CHAT_ENCRYPTION_KEY is required to enable saving; no raw audio is persisted. Saved history may be cleared. There is no graph-memory extraction or new processor. Device speech services follow the configured OS engine's privacy behavior; use installed offline voices when required.

No schema migration is needed. Existing deny-by-default RLS stays in place and all API queries are tenant scoped. Consent changes, saving, and clearing serialize per user. A monotonically advanced privacy-settings timestamp acts as the history version; clear/consent changes fence out queued saves from old screens or devices. No extra schema is needed. Turning saving off suppresses reads/new writes; explicit Clear deletes stored transcript rows. All conversation turns use the existing daily request quota and cost ledger. Failed provider attempts count and are not auto-retried.

Rollback the app/API feature before retiring the encryption key. Do not rotate the key without an explicit re-encryption migration; ciphertext fails closed with an unavailable-history error under the wrong key. Existing task data is unchanged. No production deployment or database migration is performed by this slice.
